# ADR-0017 · 主题文件：布局、明暗两个开关和公开变量

- **日期**：2026-10-24
- **状态**：提议
- **相关**：PR #176（plugins.json 格式 2）

用户只能在四个内置主题里选，也没法分享主题。我们从数据文件夹里读主题：每个主题是一个 `theme.json`，选布局、选明暗、设公开的 CSS 变量，可以再带一个 `theme.css`。

## 背景

- `<html data-theme>` 选内置主题。主题名同时决定布局和暗色：组件里 115 条选择器认 `flat`，35 条认 `dark`，11 个图表组件调用 `useIsDark`。
- 打包时生成的类名长这样：`._item_1jwc4_1`。CSS 文件一改，类名就变。
- 插件页面运行在单独的 iframe 里，CSP 不允许它加载任何外网图片和字体。主程序窗口的 CSP 挡住外网字体，外网图片只放行 `raw.githubusercontent.com`（插件市场的图标）和 `cdn-avatars.huggingface.co`（模型图标）。

## 决定

我们**把主题拆成 `<html>` 上的三个开关，并从 `<数据文件夹>/themes/<id>/` 读主题文件**。

| 属性 | 取值 | 决定什么 |
|---|---|---|
| `data-theme` | `default`、`minimal`、`flat`、`dark`、`custom` | 内置的配色 |
| `data-layout` | `card`、`flat` | 卡片还是扁平 |
| `data-mode` | `light`、`dark` | 明还是暗，组件和图表都看它 |

- 组件认 `data-layout` 和 `data-mode`，不再认主题名。内置主题看起来和以前完全一样。

| 内置主题 | `data-layout` | `data-mode` |
|---|---|---|
| 默认、简约 | `card` | `light` |
| 扁平 | `flat` | `light` |
| 暗色 | `card` | `dark` |

存在哪、叫什么：

| 存什么 | 存在哪 | 名字 |
|---|---|---|
| 主题文件 | `<数据文件夹>/themes/<id>/` | `theme.json`，可选 `theme.css` |
| 选了哪个主题 | localStorage | 键 `hindsight.theme`（现有的键），值是内置主题名，或 `custom:<id>` |
| 正在用的自定义主题的副本 | localStorage | 键 `hindsight.theme.custom`。启动时直接用它套主题，不等后端读文件，免得先闪一下内置主题 |

数据文件夹默认在 macOS 的 `~/Library/Application Support/Hindsight/` 和 Windows 的 `%APPDATA%\Hindsight\`，用户可以换到别处。插件也放在这里（`plugins/`）。

- 主题由两部分组成：`theme.json` 写布局、明暗和变量；`theme.css` 可选，能改任何东西。优先级：`theme.json` 的变量高于 `theme.css`，`theme.css` 高于内置主题。
- 自定义主题从默认主题的配色开始，`data-mode="dark"` 时换成暗色的配色，再用 `tokens` 覆盖。
- 对外的约定只有两样：公开变量的名单，和给 CSS 主题用的 `data-part` 名字。改其中任何一个名字都会弄坏别人的主题。名单只在 Rust 代码里写一份，测试保证 `tokens.css` 和文档里的 JSON Schema 跟它一致。字段和规则写在 `docs/themes/`。
- 写入只有一个入口 `install`。导入和以后的主题市场都调用它。

## 备选

- **JSON 写变量，可选 CSS 文件（选这个）**：变量给出稳定的接口，也能画预览；CSS 管其余的一切。
- **只用 JSON**：约定最稳，但名单外的东西作者都改不了。
- **只用 CSS（Obsidian 的做法）**：自由度最高，但预览只能靠截图，类名一变主题就坏。
- **选一个内置主题当底子，不拆开关**：组件不用改，但做不出暗色扁平。

## 后果

- **好处**：用户能自己做主题、分享主题。主题市场只需要下载文件、调用 `install`。
- **代价和风险**：变量名和 `data-part` 名字从此不能随便改。`data-part` 以外的选择器不保证兼容，界面一改，CSS 主题就可能坏。

## 数据、兼容性、安全和隐私

- **已有数据和迁移**：不变。`hindsight.theme` 只是多了 `custom:<id>` 一种值。不碰数据库，不迁移，不同步。
- **新旧版本混用和回退**：
  - `theme.json` 带 `format` 版本号，不认识的版本明确报错。
  - 不认识的字段和不在名单里的变量都忽略，所以新版本加了东西，旧版本照样能用这个主题。忽略的变量会列出来给作者看。
  - 旧版本不读 `themes/`，读到选的是自定义主题时用「简约」。再升级回来，主题还在。
- **不可逆的影响**：删除主题会删掉它的文件夹。
- **安全和隐私**：Hindsight 不过滤 `theme.css`，因为 CSS 的转义能绕过文字过滤（`\75 rl(` 就是 `url(`）。CSS 不能运行脚本，也不能加载外网字体，但能从上面两个域名加载图片。所以一个恶意主题能让对方知道用户的 IP 和打开时间，还能用属性选择器把元素属性里的内容（比如输入框的值）一个字符一个字符地传出去。对方能不能看到这些请求，取决于 GitHub 和 HF 的访问记录，没有核实。主题 CSS 在主程序窗口里运行，比插件页面的限制少，用户只应安装信得过的主题。
- **数据文件夹**：换数据文件夹不会搬走主题。插件也是这样。

## 验证

- 每个内置主题，拆开关前后，每个元素计算出的样式哈希相同。
- 测试检查名单、`tokens.css` 和 Schema 三者一致。

## 后续

- 主题市场：在 hindsight-plugins 里放一个 `themes.json`，安装时调用 `install`。
- 间距和字号要等组件不再写死这些值，才能公开。
- 插件页面不跟着自定义主题变（现在也不跟），要不要把主题变量传给插件，以后再定。
