# MCP server

> **状态**：草稿。只定了它在架构里的位置，详细设计走新功能流程时再写。总体结构见 [AI 后端架构](0-ai-architecture.md)。
>
> **相关**：#259

MCP（Model Context Protocol）是 AI Agent 调用外部工具的协议。Hindsight 做 MCP server 以后，Claude Desktop、Cursor 这类外部 Agent 能查 Hindsight 记录的数据，也能把写好的日报存回 Hindsight，用户在日报页里就能看到（#259）。

---

## 1. 在架构里的位置

它是 ① 的一个入口，不经过 ②：模型在外部应用那边，Hindsight 不调模型。

| 外部 Agent 做什么 | 用 Hindsight 的哪部分 |
|---|---|
| 查数据 | `Tools`，和聊天是同一份定义 |
| 拿写日报的材料 | `ReportContext`，和 Hindsight 自己写日报用的是同一份 |
| 存回日报 | 和日报入口写库是同一处 |

- 查数据和拿材料都过同一个 `AiDataPolicy`。外部 Agent 看到的，和 Hindsight 自己的模型看到的一样。
- 只能写日报。活动记录、分类、设置都不能改。
- 查数据用只读的数据库连接。写日报单独一处，只碰日报的表。

---

## 2. 两种形态

| | stdio | 本地 HTTP |
|---|---|---|
| 怎么连 | 外部 Agent 用 `--mcp` 参数启动 Hindsight 程序，通过标准输入输出通信 | 外部 Agent 连 `127.0.0.1` 上的一个端口 |
| Hindsight 要不要开着 | 不用 | 要 |
| 鉴权 | 不需要：能启动程序的就是本机用户 | 需要：本机别的程序也能连这个端口，而且它能写 |
| 先例 | 同一个程序已经有 `--ocr-worker` 模式 | 没有 |

---

## 3. 写回的日报

- **存在哪**：和 Hindsight 自己写的日报存在同一张表里。日报页照常显示；用户开了日报同步的话，也照常同步。
- **谁写的**：表里已经有一个字段记是哪个模型写的。外部 Agent 写入时，记它自己报上来的名字（提议）。
- 按段还是按天、已经有日报时怎么办，见[待决定](#4-待决定) 4、5。
